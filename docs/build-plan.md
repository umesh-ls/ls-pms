## The structure

Three pieces. Build them in this order, because each one depends on the shape of the last.

**1 · The Register** — one row per person per quarter, fixed columns, never widened for a new quarter.
This is the system. Everything else is an input method. If this schema is right now, any tool built later
is just a screen over the same table — and the migration is a copy-paste, not a rebuild.

**2 · The Review Form** — what the employee and the manager actually fill in, one person at a time.
Built from the existing LS self-appraisal form, cut down to a quarter and with the manager's side attached.

**3 · The Monthly Log** — the anti-recency-bias record. Not built yet; starts in November (see Phase 2).

## The three rules that make this work

1. **All four FY27 quarters count toward the annual rating.** Q1 and Q2 are captured retrospectively against the existing seven competencies — not new criteria.
2. **The leadership note never goes on the form.** The form travels between employee and manager, so
   anything on it is visible to the employee. Managers send that note straight to HR.
3. **Add rows, never columns.** A new quarter is new rows in the Register. The moment someone adds
   "Q3 Rating" as a column, the annual compile breaks and the data stops being queryable.

## Deliberately not in v1

KPIs per role · role-family definitions · 360 or peer feedback · skip-level views · dashboards ·
salary bands · promotion criteria.

The grade structure work is the exception — it is not part of this plan, but it sits upstream of it.
A rating feeds an increment matrix indexed on grade, and the 24 August analysis found no salary bands,
the same job title across three grades, and no written promotion definition. **Performance data arriving
in April 2027 will be correct and still indefensible if grade remains undefined.** Run that as a parallel
track, not a later one.
